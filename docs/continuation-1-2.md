# Continuation report — current basic withdrawal

This continuation targets the frozen **basic single-note paymaster route** in `tornado-ui-new-era` main, using `@kohaku-eth/tornado-cash@0.1.0-alpha.38`. The executable target digest and published CID are anchored by [verification-profile.json](../verification-profile.json) and [release correspondence](release-correspondence.md). The route checks a host-RPC receipt and exact EntryPoint/pool events before confirmation.

The source-fact mapper, conditional Z3 obligations, finite lifecycle model, captured-source tests and byte-exact rebuild checks remain the methods for the SDK/caller boundary. The separate [Lean certification](lean-certification.md) covers selected local validator properties; it does not prove the SDK, caller protocol or whole program. The scope excludes the smart-account withdrawal route, deposits, all Vue/browser behaviour, and authenticated chain consensus.

## Selected note and signed operation

1. The UI parses one Classic note on the selected chain. A short-lived same-origin frame imports that note into fresh private storage and uses a public-history projection; tests exercise secret-slice removal from reused history. The legacy-note parser splits the 62-byte preimage into nullifier and salt and derives its commitment and nullifier hash. Pedersen correctness and historical chain data remain trusted.
2. The captured SDK imports the note by commitment, checks its pool, selects the matching unspent deposit, and routes the selected nullifier/salt through the proof thunk. The basic frame disables unrelated derived/signature signer methods. Source-specific facts and a conditional dataflow proof check the selected legacy-secret path; they are not a proof of all discovery/sync algorithms.
3. In alpha.38, gas estimation passes **dummy proofs, signatures and authorization** with verifier state overrides. The SDK's estimation loop runs `simulate(gas)` for bounded gas probes and calls the real `build(gas)` only after limits converge or an eligible fallback is selected. Captured-source shape checks and integration tests distinguish estimation payloads from the final signed operation. The assumptions include faithful SDK dependencies, dummy non-executability on actual deployed contracts, and the integrity of the returned gas data.
4. The final build proves/signs locally. The host's `validateWithdrawal` checks direct recipient, zero execution calldata/gas/nonce, pool/asset/paymaster/chain, fee/net, sponsor tuple, estimation metadata, and proof-nullifier equality with `noteIdentity(note)`. The local validator's source-extracted conditional SMT obligations apply to successful return in the declared input domain; they do not prove Groth16, note ownership or Merkle membership.
5. Only after the user chooses Submit does `submitWithdrawal` revalidate the quote, compute and retain the expected UserOperation hash, and call `eth_sendUserOperation` once. A lost response or later confirmation failure leaves an unknown result with the known hash retained; the application does not automatically rebroadcast that quote. An externally received signed operation may still execute independently after this point.

## Caller ownership and scheduling

`App.vue` keeps editable form refs separate from the reviewed quote and saved settings. Its `run` lock and `sendWithdrawal` started guard execute before awaiting the adapter. The source-specific lowering checks this control skeleton; an inductive protocol abstraction proves at most one application send per quote under normal Promise/event-loop and quote-ownership premises. The Vue scheduling tests compile and mount the captured `App.vue`, delay preparation/send/confirmation stages and inject duplicate actions. They are finite implementation evidence, not a Vue-to-model refinement proof.

The standalone adapter is not single-use: calling it directly twice can send twice. Other tabs, reloads, hostile same-origin code, mutation of private quote data, and arbitrary browser scheduling are outside the proof. Quote age is checked at preflight start; a delayed connection check can pass the five-minute threshold before network send. The SDK uses dummy estimates before Submit, but no formal EVM proof of dummy non-executability is claimed.

## Confirmation evidence and trust boundary

The bundler's `eth_getUserOperationReceipt` response is used **only to locate a transaction hash**. The selected chain-read client then fetches that transaction receipt and requires success. The reconciler decodes logs and requires a matching successful EntryPoint `UserOperationEvent` (expected hash, sender, paymaster and nonce) and a matching pool `Withdrawal` event (recipient, nullifier, relayer and fee). Mismatch, absence, revert and timeout do not become confirmed. Source inspection and captured-source tests support this async path; it is not an implementation SMT theorem.

**A_CHAIN_RPC_REPORTING** remains necessary: the selected wallet/provider or configured fallback RPC must truthfully report receipt and logs from the intended chain. These reads are independent of the bundler's report but are not authenticated against a locally verified consensus header. The model therefore retains a dishonest-RPC confirmation counterexample. No finality, reorg resistance, complete balance/refund audit, or successful recipient-contract semantics are proved.

## Evidence and limits

The run emits checked source facts, replayable SMT-LIB, mutant sensitivity, concrete/symbolic correspondence, captured SDK and Vue tests, a finite lifecycle report, and exact SDK/UI rebuild and CID reports. [claims.md](claims.md) separates conditional source-linked proofs from model checks and implementation tests; [assumptions.md](assumptions.md) names the trusted primitives and environmental contracts. The final `PASS_WITH_ASSUMPTIONS` verdict is scoped to those claims and assumptions. It is not a guarantee that the published application is bug-free or that user funds cannot be lost.

The smart-account route has a different post-Submit exposure boundary: its signed operation goes to a simulation RPC before the app's bundler broadcast, and that RPC could relay it independently. This continuation does not verify that route. Compiler/toolchain correctness, gateway delivery, contract code, cryptographic circuits, live network state and the human's understanding of the displayed review remain outside the result.
