# Minimal distribution of the current verifier

The distribution retains exact source and output hashes while avoiding redundant stored copies. Storage choices do not change claim scope or promote tests into proofs.

Not stored in the distributed repository:

- The 110-file release/vendor/ copy. Identical library files come from integrity-locked npm dependencies; only two small original package-metadata files remain.
- The 30 duplicate SDK artifact/package entries. The baseline checker reads their exact bytes from the locked installed SDK and checks their captured hashes.
- The 23 duplicate generated application outputs. The release stage rebuilds the complete 65-file directory, compares every original hash and inventory entry, and computes its CID directly.
- Pre-generated proof IR, Lean source/compiled outputs, SMT queries, corpus, mutants, reports and logs. They are regenerated by verification and ignored by Git. The authored network-blocking guard lives under scripts/.
- The obsolete capture stub.

Retained inputs include the auditable frozen UI/SDK source, original SDK root metadata, complete target/output manifest, exact compressed offline assets, proof/model/test code, the pinned Lean toolchain declaration, claims/assumptions, pinned build descriptors/lockfiles and deployment/source-capture records. The `.gitignore` exclusions for `.DS_Store`, `.env` and `.env.local` are preserved.

About 49 MiB is the exact gzip packaging of public proving/history/relayer inputs. These files do not come from npm. Gateway probes returned HTTP 429 during cleanup, so these inputs are retained to avoid making setup depend on gateway availability. No public gateway is contacted during verification.

A fresh export should complete setup and full offline verification without pre-generated outputs or original developer checkouts. Maintainer validation checks tampered source/package bytes, a local SDK link, missing tools, altered output CID and the exact-source policy. Reports are generated locally; no precomputed PASS is required. The current target is defined by [the verification report](release-verification-v1.md).
