# Minimal distribution of the current verifier

Repository cleanup changes storage and installation, not the target, source semantics, eight claims, assumptions or expected CID. The immutable target manifest retains its original digest and output hashes.

Removed from the distributed repository:

- The unused history/ archive of the previous verifier. Its earlier digest/CID remain in release-history.md.
- The 110-file release/vendor/ copy. Identical library files come from integrity-locked npm dependencies; only two small original package-metadata files remain.
- The 31 duplicate SDK artifact/package files. The baseline checker reads their exact bytes from the locked installed SDK and checks their captured hashes.
- The 23 duplicate generated application outputs. The release stage rebuilds the complete 65-file directory, compares every original hash and inventory entry, and computes its CID directly.
- Pre-generated proof IR, SMT queries, corpus, mutants, reports and logs. They are regenerated by verification and ignored by Git. The authored network-blocking guard lives under scripts/.
- The obsolete capture stub.

Retained inputs include the auditable frozen UI/SDK source, original SDK root metadata, complete target/output manifest, exact compressed offline assets, proof/model/test code, claims/assumptions, pinned build descriptors/lockfiles and deployment/publication-cleanup records. Your .gitignore additions for .DS_Store, .env and .env.local are preserved.

About 49 MiB is the exact gzip packaging of public proving/history/relayer inputs. These files do not come from npm. Gateway probes returned HTTP 429 during cleanup, so these inputs are retained to avoid making setup depend on gateway availability. No public gateway is contacted during verification.

A fresh export must complete setup and full offline verification without caches, pre-generated outputs or original developer checkouts. Maintainer validation also checks tampered source/package bytes, a local SDK link, missing tools, altered output CID and strict publication-cleanup policy. Reports are generated locally; no precomputed PASS is required.
